# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Bounded is a Scala 3 (3.3 LTS) library, cross-built and published for Scala 2.13 as well, built with sbt 2, for building CQRS / event-sourced Domain Driven Design applications on Apache Pekko (migrated from Akka). It is published to Maven Central as `io.cafienne.bounded` artifacts. The version comes from git tags (see Releasing); don't hardcode it.

## Commands

sbt 2 build with three published modules aggregated by the root project. sbt 2 starts a thin client that sends all its arguments to a background server as *one* command line: chain commands as `sbt "clean; test"`, never `sbt clean test` (that fails with "value test is not a member of Boolean"). After such a failure the server can be left in a broken state; `sbt shutdown` resets it.

```bash
sbt compile                      # compile all modules (scalafmt runs on compile)
sbt test                         # all tests (Scala 3, the default scalaVersion)
sbt "++2.13.18; test"            # all tests on Scala 2.13
sbt "+test"                      # all tests on both (also +compile, +Test/compile, +publishLocal)
sbt boundedCore/test             # one module (also boundedTest, boundedPekkoHttp, boundedPekkoProjection)
sbt "boundedCore/testOnly io.cafienne.bounded.aggregate.TypedCommandGatewaySpec"
sbt "boundedCore/testOnly *TypedCommandGatewaySpec -- -z \"some test name\""
sbt "coverage; test; coverageReport" # what CI runs (CircleCI machine executor with Temurin 25, then `++2.13.18; test`, then SonarCloud scan; coverage stays on Scala 3)
sbt scalafmtAll                  # format; config in project/.scalafmt.conf (scalafmt 3, scala3 dialect, maxColumn 120)
sbt headerCreate                 # license headers (sbt-header, auto-applied via AutomateHeaderPlugin)
sbt dependencyUpdates            # sbt-updates
```

Notes:
- `scalafmtOnCompile := true`, so compiling rewrites source files — expect formatting diffs after a build.
- Compiler runs with `-deprecation -feature -unchecked -Wvalue-discard`, plus `-Wunused:all` on Scala 3 and `-Xsource:3 -Wunused:imports,privates,locals,implicits,nowarn` on 2.13; keep code warning-clean on both.
- **The sources are shared by Scala 3 and 2.13** (`crossScalaVersions` in `basicSettings`). `-Xsource:3` lets 2.13 accept `?` wildcards, `xs*` splices and `case _: A | _: B`, but code must not use Scala 3-only constructs: no `(using x)` at call sites (pass implicits as a plain argument list; declare them `implicit`), no `scala.compiletime` (`var x: T = _` instead of `uninitialized`), no polymorphic function types (a trait with a polymorphic `apply`, as `BoundedR2dbcProjection.Build`), no `given`/`enum`/`extension`/`opaque`/`inline`. Something that truly needs both variants goes in `src/main/scala-3/` and `src/main/scala-2.13/`. Don't enable scalafmt's `rewrite.scala3` rules. Check with `sbt "+Test/compile"`.
- sbt 2 writes all build output under the root `target/out/jvm/scala-<version>/<module>/` (not `<module>/target/scala-<version>`); the Sonar coverage report paths in `sonar-project.properties` contain the Scala version and must follow `scalaVersion`.
- sbt 2 caches compile and test results by their inputs: `test` skips suites that passed with the same inputs before (even from an earlier `testOnly`), and a cached compile does not show its warnings again. To see every warning, `clean` the module first. A `++<version>` stays in effect in the sbt server for later commands; `sbt shutdown` resets it.
- The bounded-test helpers (`TestableAggregateRoot`, `TestableProjection`) start a test with `givenEvents(...)` (named `given` before Scala 3, where `given` became a keyword). Don't use Scala keywords as identifiers, not even with backticks.
- Every source file carries the `Copyright (C) 2016-<year> Batav B.V.` header generated by sbt-header.
- All dependency versions live in `project/Dependencies.scala`, kept in line with the casefabric case-engine build. `Dependencies.schemes` relaxes sbt's Slick 3.5 → 3.6 binary-compatibility check (pekko-persistence-jdbc is built against 3.5) and `Dependencies.overrides` pins Netty and `slick-hikaricp`; both are wired into `basicSettings` in `build.sbt`.

## Releasing

Same setup as the casefabric case-engine:
- **Version** is derived from `git describe --tags` by sbt-git and `project/GitInfoAnalyzer.scala`. Tags are `vX.Y.Z` (the `v` is stripped). A commit that is exactly on a tag, with no uncommitted changes, builds version `X.Y.Z`; anything else (later commits or local changes) builds `X.Y.(Z+1)-SNAPSHOT`. There is no `version.sbt` and no sbt-release.
- **`io.cafienne.bounded.BuildInfo`** is generated in `bounded-core` (version, git commit/branch, a `buildDescription` of the git state). Unlike in case-engine, `description` itself is left alone because it goes into the published pom.
- **Publishing** uses sbt's built-in Sonatype Central support, with credentials from `~/.sbt/sonatype_central_credentials` and artifacts signed by sbt-pgp. Snapshots are published straight to the Central snapshots repository; releases are staged locally (`localStaging`) and then uploaded:

```bash
git tag v1.0.0 && git push origin v1.0.0
sbt "+publishSigned; sonaRelease"    # both Scala versions in one deployment; or sonaUpload to release manually
```

Both Scala versions get the same version. `+publishSigned` alone publishes a snapshot of both.

## Modules

- `bounded-core` — the framework (aggregates, command gateways, event materializers, offset stores). Pulls in LevelDB, in-memory (`io.github.alstanchev:pekko-persistence-inmemory`), Cassandra and JDBC/R2DBC persistence plugins.
- `bounded-test` — test helpers for users of the framework (`TestableAggregateRoot`, `TestableProjection`, `TestTypedCommandGateway`, …). It is a main (not test) artifact.
- `bounded-pekko-http` (sbt id `boundedPekkoHttp`) — Pekko HTTP helpers (`PekkoHttpParameterOffsetConverters`).
- `bounded-pekko-projection` (sbt id `boundedPekkoProjection`) — runs Bounded read models as Pekko Projections. Public API: `EventProjection` (name, aggregate type, filter), the factories `BoundedJdbcProjection` / `BoundedSlickProjection` / `BoundedR2dbcProjection` (`exactlyOnce`, `atLeastOnce`, `atLeastOnceAsync`, `groupedWithin`, `groupedWithinAsync`) and `BoundedCassandraProjection` (`atLeastOnce`, `groupedWithin`), `BoundedR2dbcProjection.sliceRanges` / `SliceRange`, and `BoundedProjections.runLocally` / `runInCluster` (`ShardedDaemonProcess`). Each factory method calls the Pekko method of the same name with the source for the journal, a filtering handler and the `EventProcessed` status observer, then passes the Pekko projection through an `adjust` hook for Pekko's own `with...` methods (a `withStatusObserver` there replaces the `EventProcessed` observer). The sources, handlers (`BoundedHandlers`, the private handlers in each factory), `ProjectionEnvelope` and `publishEventProcessed` are `private[projection]`. JDBC, Slick and Cassandra refuse the R2DBC journal (their offset stores have no `TimestampOffset`); `BoundedR2dbcProjection` reads by slices on R2DBC (optionally one `SliceRange`, id key `type-min-max`) and by tag elsewhere, so its results are typed `[Offset, ?]`. `atLeastOnceFlow` has no factory. The store projection modules (`pekko-projection-jdbc`, `-slick`, `-r2dbc`, `-cassandra`) are `Optional` dependencies, so each store has its own object. Its tests depend on the `bounded-core` tests (`test->test`) for `Notes`, `R2dbcPostgres` and the Cassandra config of `CassandraAggregateTypeMigrationSpec`.

The codebase was migrated from Akka to Pekko: packages are `io.cafienne.bounded.pekko...`, and all config keys must use the `pekko.` prefix — Pekko silently ignores `akka.*` keys, so a leftover one compiles and runs but has no effect (or throws `ConfigException.Missing` when read with `getString`). The one intentional exception is the `CassandraOffsetStore` constructor's default keyspace, which stays `akka` so direct users keep their table. Through `ReadJournalOffsetStore` the offset table lives in `bounded.eventmaterializers.cassandra-offsetstore.keyspace` when set, else in the keyspace of the old top-level key `cassandra.journal.keyspace` / `cassandra-journal.keyspace` (which older versions required, so upgraded deployments keep their offsets), else in the journal plugin's keyspace (`pekko` by default).

## Architecture

The flow is: command → command gateway → aggregate root (persists events) → event journal → event materializers (projections / combined logic) → query stores.

**Protocol** (`aggregate/Protocol.scala`): `DomainCommand` (carries `aggregateRootId`), `DomainEvent`, and the handling result `Reply` = `Ok(events)` | `Persisted(events, EventPosition(persistenceId, sequenceNr))` | `Ko(HandlingFailure)`. `Persisted` is what a classic aggregate with `replyWithPosition = true` replies (default off: `Ok`), and what a typed one builds with `AggregateBehavior.positionOf(context, persistenceId)` (needs `Behaviors.setup`); a command without events stays `Ok(Nil)`. Opt-in metadata (`aggregate/MetaData.scala`): `CommandMetaData` / `EventMetaData` carried by commands and events that extend `HasCommandMetaData` / `HasEventMetaData`, passed on by the aggregate with `EventMetaData.causedBy(command.metaData)` (and `CommandMetaData.causedBy(event)` in policies); it travels inside the events because Pekko's typed persistence has no public per-event metadata API. Required metadata on every command/event was removed on purpose in 0.3.0 (#62); keep it opt-in.

**Aggregate types** (`aggregate/AggregateType.scala`): every aggregate has a required `AggregateType(name)` (non-empty, no `|`), defined once and used on both the write and read side. Persistence ids are `type|id`, built with `AggregateType.persistenceId` (not Pekko's `PersistenceId(type, id)`, which refuses ids containing `|`); read the id back with `AggregateType.aggregateIdOf(persistenceId)`, because `PersistenceId.entityId` takes `a|b|c` for a replication id. On tag-based journals every event is tagged with the type name; on the R2DBC journal the type is the entity type. The name is permanent, because it is part of every persistence id.

**Two aggregate styles coexist:**
- *Classic*: `AggregateRootActor[A]` is a Pekko classic `PersistentActor`. Implementers provide `aggregateId`, `handleCommand(cmd, Option[A]): Reply` and `newState(evt)`; state evolves via `AggregateState.update(evt): Option[A]`. The actor persists `Ok` events, updates state, optionally snapshots (`snapShotInterval`) and replies with the `Reply`. Implementers also define the abstract `aggregateType`; the final persistence id is `aggregateType.persistenceId(aggregateId)` (`persistenceIdPrefix` from 1.0.0 is gone). With `snapShotInterval` set it saves a snapshot every n events and deletes the older ones (`deleteOlderSnapshots`). An event is wrapped in `Tagged` only when it has tags: on tag-based journals always (`tags(event) + aggregateType.name`), on R2DBC only when `tags(event)` is non-empty. Override `tags(event)` for extra tags (only tag-based journals can query them). A write-side event adapter bound to an event class does not see an event wrapped in `Tagged`. Created via `AggregateRootCreator.props(id)` and routed by `DefaultCommandGateway` / `RouterCommandGateway` (`aggregate/CommandGateway.scala`).
- *Typed*: `typed.TypedAggregateRootManager[T]` supplies `behavior(persistenceId: PersistenceId): Behavior[T]` and an `entityTypeKey`, whose name is the `aggregateType`. Gateways call `behaviorFor(aggregateRootId)`, which passes `PersistenceId(type, id)`; the behavior must use that id and tag with the type, which `typed.AggregateBehavior(...)` does (bounded-test's typed `TestableAggregateRoot` throws `PersistenceIdMismatch` otherwise). `DefaultTypedCommandGateway` is a local gateway: a guardian actor spawns aggregates on demand by id and stops them after `aggregateMayIdleFor` (default 6 min). `ask` takes a `ActorRef[Res] => T` command factory.

**Clustering.** `DefaultTypedCommandGateway`, the classic gateways and `EventMaterializers` are node-local: in a cluster two nodes would start two actors on one persistence stream, and every node would run every materializer. For a cluster use `typed.ShardedTypedCommandGateway` (Cluster Sharding; builds an `EntityTypeKey[Cmd]` from the manager's key name, so it needs a `ClassTag`; `shutdown()` gracefully shuts down the node's shard region) and `ClusteredEventMaterializers` (a `ShardedDaemonProcess`, one process per materializer, numbered by sorted `viewIdentifier`; a runner replays, listens and stops on hand-off through `StoppableResumable.registerListenerWithKillSwitch`). Classic aggregates have no clustered gateway. `ReplySerializer` (bound in `bounded-core`'s `reference.conf` to `Ok`, `Ko`, `PersistenceFailed`, `PersistenceRejected`, `UnexpectedCommand`) writes nested events/failures/commands with their own Pekko serializer; a failure cause becomes a `RemoteFailureCause`.

The gateways' own messages (classic `AggregateControl`, the typed guardian protocol in the `DefaultTypedCommandGateway` companion, which has no outer reference so 2.13 needs no `@nowarn`) are `NoSerializationVerificationNeeded`, so `serialize-messages = on` only needs serializers for the application's commands and replies (`SerializeMessagesGatewaySpec`). The typed `TestableAggregateRoot.whenAsk` / `whenAskAll` send commands with a reply probe and wait for the replies (also after a `pipeToSelf` step), exposing `reply`, `replies` and a `Ko` as `failure`.

Both gateways run commands through an implicit `ValidateableCommand[T]` (`CommandValidator`) before delivery; validation failures surface as `CommandValidationException`.

**Event materializers** (`eventmaterializers/`): a materializer names its `aggregateType` (combined logic its `aggregateTypes`) and reads it through `ReadJournalProvider.aggregateTypeJournal`, an `AggregateTypeReadJournal` (`currentEventsByAggregateType` for replay, `eventsByAggregateType` for listening). The read journal follows the suffix of `pekko.persistence.journal.plugin`: on leveldb, cassandra, jdbc and `inmemory-journal` a type is read by tag (`TagAggregateTypeReadJournal`); on R2DBC, which has no queries by tag, `R2dbcAggregateTypeReadJournal` reads the entity type through `eventsBySlices`, dropping backtracking duplicates, loading missing payloads and filling sequence-number gaps (dedup capacity `bounded.eventmaterializers.r2dbc.deduplicate-capacity`). After a restart it re-delivers the backtracking window before the stored offset, so delivery is at-least-once. `ReadJournalProvider.readJournal` (raw tag queries) still throws on R2DBC. Pekko's bundled `pekko.persistence.journal.inmem` has no query side, so anything that uses materializers must run on `inmemory-journal` (or a real store).
- `AbstractEventMaterializer` → live listening; `AbstractReplayableEventMaterializer` adds `replayEvents()` with `handleReplayEvent`; `CombinedLogicEventMaterializer` for combined logic (reacts to the events of several aggregate types, offset per type as `TagOffsets`, no replay). `MaterializerEventFilter` filters events at runtime.
- `EventMaterializers(list).startUp(keepListenersRunning)` replays all `ResumableReplayable`s first, then registers live listeners from the replayed offset.
- With `withPartialReplay = true` the offset is persisted after each event so replay resumes; `false` replays from `NoOffset` every time.
- `migration.AggregateTypeMigration` converts a journal written without aggregate types (1.0.0 and earlier) into `type|id` streams: `dryRun`, `migrate` (resumable copy that checks what a target already holds, split of mixed streams, snapshot copy, verify), `deleteMigrated`, `oldStreamsReadableByType` (old events still readable by tag, which Cassandra and the in-memory journal keep after a delete), `startAtEnd` / `startCombinedLogicAtEnd` (materializers and combined logic skip the copies) and `resetOffsets` (full replay). By default it looks at every stream: those the rule maps onto themselves are in place, and the report lists in-place streams whose events lack the type tag. Plans where two old streams share a target, or a target is itself migrated, are refused as conflicts. It must run while the application is stopped; `AggregateTypeMigrationSafetySpec` covers the refusal cases.
- **Waiting for the read side** (`readside/`): with `bounded.eventmaterializers.publish` on, projections (their status observer in `BoundedProjections.publishEventProcessed`) and listening materializers (`EventStreamHandling`) publish `ProjectionProgress` for every event (filtered ones too), `ProjectionFailure` (`isFinal` when the recovery strategy gives up; a projection counts attempts per envelope and reads the retries of Pekko's internal strategy case classes through `Product`, `BoundedProjections.retriesOf`) and `ProjectionDown`, keyed by a stable `readSideId` (`EventProjection.readSideId` = projection id, shared by all slice ranges; a materializer's `viewIdentifier`). The `ReadSideRegistry` extension listens on the event stream; `awaitProcessed(readSideId, position, timeout)` gives `Processed`, `Pending(TimedOut | Down(cause))` or `Failed(cause)` as values (none means the command failed) and fails the future only for an unregistered read side, publishing off or a terminating system. Read sides register themselves when built (projections) or when they start listening (materializers; replay publishes nothing). Settings `bounded.read-side.timeout` / `idle-retention`. Node-local.
- **Event serialization** (`serialization/VersionedJsonSerializer.scala`): a `SerializerWithStringManifest` base with `EventFormat`s (name, version, spray-json codec, an upcaster per older version), manifest `<name>.v<n>`; `EventFormat.withMetaData` stores `EventMetaData` as `{"meta", "data"}`. Pekko itself refuses duplicate serializer ids at startup; the base refuses ids 0–40. `bounded-test`'s `EventFixtures` checks a folder of `<name>.v<n>.json` fixtures against it.
- Offset stores (`offsetstores/`): in-memory, LMDB, Cassandra, JDBC, R2DBC, all encoding offsets through `OffsetCodec`. `ReadJournalOffsetStore` picks the store that matches the journal (R2DBC included). `OffsetStoreProvider` (mixed into an `ActorSystemProvider`) selects in-memory or LMDB from `bounded.eventmaterializers.offsetstore.type`.

## Tests

ScalaTest with Pekko testkits (`actor-testkit-typed`, `persistence-testkit`, `projection-testkit`). `bounded-core` tests run in a forked JVM with `--add-opens` for `java.nio` and `sun.nio.ch`, which lmdbjava (`LmdbOffsetStore`) needs on Java 17+; users of the LMDB offset store need the same flags. Shared test config is in `bounded-core/src/test/resources/reference.conf`; `SampleProtocol.scala` and the `ClassicSimpleAggregate` / `TypedSimpleAggregate` classes are the reference examples for writing aggregates.

The offset store specs for Postgres (R2DBC) and Cassandra, `R2dbcAggregateTypeSpec`, `R2dbcAggregateTypeMigrationSpec` (both on `R2dbcPostgres`, which applies `r2dbc/create_tables_postgres.sql`) and `CassandraAggregateTypeMigrationSpec` (tables auto-created, a recent `first-time-bucket` and a short `eventual-consistency-delay`) start containers with Testcontainers and are canceled without Docker; JDBC is tested on H2 (`JdbcAggregateTypeMigrationSpec` runs the JDBC journal on H2, creating its tables with the plugin's `SchemaUtils`).

Persistence backends differ per kind of test:
- Aggregate and gateway specs use Pekko's `pekko.persistence.journal.inmem` (or `PersistenceTestKitPlugin.config`), set inline in the spec's testkit config.
- Materializer and projection specs (`AbstractReplayableEventMaterializerWithRuntimeEventFilterSpec`, `TestableProjectionSpec`) need a read journal and use the `SpecConfig.testConfig` objects (one per module), which configure `inmemory-journal` / `inmemory-read-journal`. The core one tags events via `TestTaggingEventAdapter` (tag `testar`).
- Cluster specs (`io.cafienne.bounded.cluster`: `ReplySerializerSpec`, `ShardedTypedCommandGatewaySpec`, `ClusteredEventMaterializersSpec`) form a cluster of actor systems in one JVM with `ClusterNodes` (artery on port 0, Java serialization off, a shared JDBC journal on in-memory H2). Their aggregate is `Notes`, which replies with Bounded's `Reply`, with the hand-written `NotesSerializer`.
- Specs that extend `ScalaTestWithActorTestKit` get a typed system with a custom user guardian: create classic actors via `system.classicSystem.asInstanceOf[ExtendedActorSystem].systemActorOf(...)`, and call `super.afterAll()` when overriding `afterAll` so the system shuts down.
